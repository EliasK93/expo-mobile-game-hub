# 2048

Read this before working on 2048. The hub-wide rules are in `CLAUDE.md`: the gate, tests, git, Herdr, tooling, the shared components and the palette. Everything specific to 2048 lives here and nowhere else. Where this document and the repository disagree, the repository wins.

**Status (2026-10-17):** T1 (logic) and T2 (playable) are done; next is T3 in plan mode (rule 10). The decisions below are settled; don't ask about them again.

## Overview

2048 is the third game in the hub: slide numbered tiles on a square board; two equal tiles that collide merge into their sum. Reach the win tile, then keep going for a high score until no move is left.
- It lives in `src/games/2048/`.
- Its route is `src/app/2048.tsx` (route `/2048`, game id `'2048'`), the screen wrapped in the hub's `GameRoute`, which records playtime.
- Its entry is in `src/games/registry.ts`, with a `Tile` for the art on home.
- Identifiers can't start with a digit: components are named `Game2048…` (e.g. `Game2048Screen`, `Game2048Tile`).

It follows the patterns Sudoku established; see `docs/sudoku.md`.

## Spec (v1)

- **Boards:** 4×4, 5×5, 6×6 and 7×7. Each size has its own **win tile**:

  | Size | Win tile |
  |---|---|
  | 4×4 | 2048 |
  | 5×5 | 4096 |
  | 6×6 | 8192 |
  | 7×7 | 16384 |

- **A move:** swipe up, down, left or right. Every tile slides as far as it can in that direction.
  - Two equal tiles that meet merge into one tile of their sum; the sum is added to the score.
  - Each tile merges at most once per move. Merges are resolved from the side the move goes to: a row `2 2 2 2` moved left gives `4 4`, `2 2 4` gives `4 4` (not `8`), `4 4 8` gives `8 8`.
  - A swipe that changes nothing is not a move: no new tile, no undo step.
  - After every real move one new tile appears on a random empty cell: a **2** (90 %) or a **4** (10 %).
- **Start:** a new game starts with two random tiles.
- **Win:** the first time the size's win tile appears, an overlay on the board says **You win!** with **Keep going** (primary) and **New game**. Keep going continues the same game; the overlay never appears again in that game.
- **Game over:** when no move can change the board (no empty cell, no equal neighbours), the game ends: the board dims with **Game over** on it, and the stats panel opens (T3); its Close returns to this finished board.
- **Undo:** one step back.
  - **Undo** restores the board and score from before the last move (the tile that spawned after it disappears too).
  - Only one step: after an undo, Undo is disabled until the next move.
  - Disabled at the start and after game over.
  - A game in which undo was used **counts** (played, win) but **stays out of the best score and best tile**, like Sudoku's hinted wins.
  - Undo restores only the board and score: a win already reached stays (`won`, `keptGoing`). Undo is therefore hidden while the win overlay is open; after Keep going it works again.
- **Score:** the sum of all merges. Two boxes above the board, like the original: **Score** and **Best** (the best score of this size). Best is live: the stored best, or the current score once it is higher; in a game with undo it shows the stored best only (`liveBest` in `logic/stats.ts`).
- **No timer.** 2048 is about score, not speed. Playtime is counted by the hub (`GameRoute`) anyway.
- **Input:** swipe on the board only (a mouse drag in the web preview). There are no arrow buttons and no physical keyboard input (touch only, no web-only code, same as Sudoku). Swipes outside the board do nothing.
- **Accessibility:** the board offers the four moves as accessibility actions (`up`, `down`, `left`, `right`, labelled "Move up" etc.). Screen readers can play, and the route tests use them instead of faking a gesture.
- **Buttons:** **Undo** and **New game** in one slim row (the shared `Button` with `compact`) between the score boxes and the board.
- **New game** opens the **size picker** (like Sudoku's level picker): 4×4 … 7×7, the last used size marked, each with its best score once it has one, plus **Cancel** while a game is running.
- **Abandon:** starting a new game while one is running ends the running game and records it like a game over (played, its score and best tile for the bests unless undo was used, a win if it already reached the win tile). Only a **started** game (at least one move) is recorded; an unstarted one just disappears.
- **Stats**, kept **per size**: games played, wins (reached the win tile), best score, best tile. A score of 0 never becomes the best score (no "best 0").
- **Stats panel:** a whole-screen panel with a size switch (see the decision below).
  - It takes the whole screen below the header (the board is hidden while it is open), with a **4 · 5 · 6 · 7** size switch opening on the current game's size.
  - **After game over** it opens by itself with the result line (`Score 12,345 · best tile 1024`, `New best!` when it is one, `with undo` when undo was used), that size's stats, **Play again** (primary, same size), **Change size** (the picker) and **Close** (back to the finished board).
  - **From the header "Stats" button** it opens anytime: no result line and no new-game buttons while a game runs; Close returns to the game.
- **Save and resume:**
  - The game is saved after every move and undo.
  - Opening 2048 with an unfinished game **resumes it directly**, no prompt (like the original; there's no clock to protect).
  - Opening it without one starts a new game of the **last used size** at once (4×4 the very first time).
  - A finished game deletes the save. The undo step is not saved: after a resume, Undo is disabled until the next move.
- **Animations** (the signature feel):
  - Tiles **slide** to their new place (about 100 ms), a merged tile **pops** briefly (about 100 ms), a new tile **appears** by growing in (about 100 ms).
  - A swipe during an animation finishes the running animation at once and applies the new move: no swipe is lost.
  - Reduced motion (the system setting) means no animation: the board changes at once.

## Decisions (decided 2026-10-17), with reasons

- **Swipe only, no arrow buttons** (user). Reason: the original's feel, and the board gets all the room. The risk (the Android back gesture from the left edge) is an Android check.
- **Board sizes 4×4 to 7×7, chosen in a picker on New game** (user). Reason: bigger boards are longer, relaxed games; the picker is the pattern Sudoku already has, and it costs no screen space during a game.
- **The win tile scales with the size** (user): 2048, 4096, 8192, 16384. Reason: 2048 on a 7×7 board is far easier than on 4×4; scaling keeps "You win!" a real achievement on every size.
- **Win, then Keep going** (user). Reason: like the original; the high score keeps the game interesting after the win.
- **One undo step, and a game with undo stays out of the bests** (user). Reason: one undo forgives a mis-swipe without making the game trivial; the same rule as hinted wins in Sudoku keeps the bests meaningful.
- **Original colour ramp, toned to sit on the paper background** (user). Reason: players recognise 2048 by its beige → orange → gold tiles; the paper background and graphite text keep it part of the hub.
- **No timer** (user). Reason: score is the measure in 2048; the hub counts playtime anyway.
- **Resume directly, no Continue prompt** (user). Reason: 2048 games are long and there's no clock; the original simply shows the board.
- **Undo is hidden while the win overlay is open; undo keeps a reached win** (user, 2026-10-17, T1 review). Reason: the spec's undo restores board and score only; hiding Undo on the overlay avoids a "You win!" over a board without the win tile, with no extra logic.
- **Live Best box** (user, 2026-10-17, T2 plan). Reason: like the original; a game with undo never shows a best it can't keep.
- **Game over dims the board with "Game over"** (user, 2026-10-17, T2 plan). Reason: the finished board stays visible behind the result, also after the stats panel's Close.
- **Home tile: a 4×4 mini board in the ramp colours, no numbers** (user, 2026-10-17, T2 plan). Reason: the tile is the game's art drawn in code, not a screenshot.
- **Best score only from scores above 0** (user, 2026-10-17, T1 review). Reason: a started game without a merge would otherwise show "best 0" in the picker.
- **Abandoning a started game records it like a game over** (user). Reason: the score reached is real, and the picker's Cancel prevents accidents; unstarted games cost nothing.
- **No hint.** Reason: the original has none, and a "best move" would need a search on the phone (heavy work, see CLAUDE.md).
- **Stats per size in a whole-screen panel with a size switch, plus a header button.** Reason: it fits on a phone, which was confirmed there.
- **Animations with React Native's `Animated`, not Reanimated.** Reason: no new package (rule 13); Reanimated is installed but unused.
- **Swipe detection with React Native's `PanResponder`.** Reason: built in, works with touch on Android and with the mouse on the web. `react-native-gesture-handler` is installed but used nowhere yet; T2 checks the SDK 57 docs and switches only if `PanResponder` falls short.
- **Accessibility actions for the four moves.** Reason: accessible play, and route tests can move without simulating a gesture.
- **Colours:**
  - The page stays paper (`background`); the board frame and the tiles use the 2048 ramp. Numbers: graphite on 2 and 4, white on the rest (like the original).
  - Starting values to tune in the browser:

## Lessons from Sudoku built into this design

- **Nothing heavy on the phone.** A move is a few array operations on at most 49 cells; there is no search and no generated data.
- **Fit without scrolling.** The screen measures its own height with `onLayout` (no header-height guess) and sizes the board from it and from the window width. No ScrollView; the bottom safe area stays free. Check 360×640 and 320×568 in the browser device toolbar, with a 7×7 board.
- **Number size by digit count and tile size.** On a 7×7 board a tile is about 40 px, and 16384 has five digits: the font size comes from the tile size and the number's length, computed in one place.
- **Text centring on Android:** numbers use the shared `glyphStyle` (`src/components/glyph-style.ts`). Button labels span the full width (the shared `Button`).
- **Panels replace controls; they never stack.** The stats panel takes the whole screen below the header; the size picker takes the place of the board and buttons; the win overlay covers only the board.
- **Header buttons get a right margin** (the Stats button first sat flush against the edge).
- **Stats are written after the save is deleted,** in one function, so a crash can't count a game twice (Sudoku's order).
- **Tests go through the real route** (`renderRouter`) with the AsyncStorage mock only. Reduced motion is mocked on, so animations are instant; one test runs with motion on and fake timers. Random is predictable: the logic takes a `Random` (`mulberry32` in logic tests); the UI passes `Math.random`, which route tests replace with `jest.spyOn`, and they start from hand-built boards by mocking `newGame` (like Sudoku). Unmount and settle at the end of a test that checks the save (a late save can land in the next test).
- **Shared hub pieces:** `components/button` (`primary`, `compact`, `COMPACT_HEIGHT`), `components/game-route` (playtime), `components/glyph-style`, `lib/storage`, `lib/random`, `lib/history` (only if it fits the one-step undo; otherwise a single saved snapshot is enough), the theme tokens.

## Architecture and storage keys (planned)

```
src/games/2048/
  logic/            # pure TS, unit-tested; the ESLint purity rule applies
    board.ts        # Board = (Tile | null)[] of size n×n, Tile = { id, value }; SIZES (4..7), winTile(size)
    move.ts         # move(board, dir) -> { board, moved, gained, slides, merges }: the classic merge rules above;
                    # slides/merges say which tile ids went where, for the animation
    spawn.ts        # spawn(board, random): one 2 (90 %) or 4 (10 %) on a random empty cell
    game.ts         # Game { size, board, score, won, keptGoing, undoUsed, prev, nextId, moves, status }; newGame(size, random),
                    # play(game, dir, random), undo(game), keepGoing(game), isOver, isStarted; pure transitions
    stats.ts        # per size: played, wins, bestScore, bestTile; recordGame(stats, size, result) with the undo rule
    save.ts         # keys, versions; toSave/fromSave (values only, ids rebuilt on load; no undo step), fromStats, fromSettings
  ui/
    game2048-screen.tsx, board.tsx, use-game2048.ts, size-picker.tsx, stats-panel.tsx, tile.tsx (home art)
```

Storage keys, all versioned (`{ version, data }`, version 1 each):
- `2048:save`: `{ size, values, score, won, keptGoing, undoUsed, moves }`, the unfinished game.
- `2048:stats`: `{ 4: …, 5: …, 6: …, 7: … }`, one entry per size.
- `2048:settings`: `{ size }`, the last used size.

## Android checks

- [ ] Swipes register reliably on the board in all four directions, also short ones; a swipe that starts near the left edge of the board moves the tiles instead of triggering Android's back gesture.
- [ ] The slide, pop and spawn animations run smoothly on a 7×7 board; with Remove animations on (Settings, Accessibility) the board changes at once.
- [ ] Numbers are vertically centred on the tiles (shared glyph style) and five-digit numbers fit a 7×7 tile.
- [ ] Score boxes, the Undo · New game row and the board fit without scrolling on the phone for every size; nothing sits under the navigation bar; the slim buttons tap accurately.
- [ ] The tile colours look like 2048 in light and dark mode, and the numbers are readable on every tile.
- [ ] The size picker, the win overlay and the stats panel fit without scrolling; the header Stats button sits clear of the screen edge.
- [ ] An unfinished game survives closing the app and comes back directly, at the same score.
- [ ] The 2048 home tile looks right next to Sudoku.
- [ ] With TalkBack on, the board offers Move up/down/left/right as actions and they move the tiles, and the board's value (row by row) is read aloud (react-native-web ignores accessibility actions, so this is untested in the browser).
